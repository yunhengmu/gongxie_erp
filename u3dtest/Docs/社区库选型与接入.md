# 社区库选型与实际接入

> 目标：让 PLC / IoT 平台 / 工业机器人这几类设备从「模拟」走到「可接真机」。
> 本文档记录**实际装进来的库、被排除的库及原因**，以及每个库的版本约束。

## 一、结论速览

| 设备 | 库 | 版本 | 目标框架 | 许可 | 状态 |
|---|---|---|---|---|---|
| Siemens S7 PLC | **S7netplus** | 0.20.0 | netstandard2.0 | MIT | ✅ 已装入 |
| IoT 平台 / 云端 | **MQTTnet** | **4.3.7.1207** | netstandard2.1 | MIT | ✅ 已装入 |
| ABB 工业机器人 | 无需库 | — | — | — | ✅ 已实现（纯 HTTP） |
| Modbus 设备 | FluentModbus | 5.3.2 | netstandard2.0 | — | ❌ 见 §4 |
| AGV 路径 / 传送带 | realvirtual.io | — | — | 商业 | ❌ 见 §4 |
| 无人机 ROS2 | ROS-TCP-Connector | 0.7.0 | UPM | Apache-2.0 | ⚠️ 见 §4 |

DLL 位置：`Assets/Plugins/S7.Net.dll`、`Assets/Plugins/MQTTnet.dll`

## 二、为什么这两个能直接用

Unity **不消费 NuGet**。能用与否只看一件事：**包里有没有 `netstandard2.1`（或 2.0）的构建，且依赖能否满足**。

### S7netplus 0.20.0

```
lib/net452/  lib/net462/  lib/net5.0/  lib/net6.0/  lib/net7.0/
lib/netstandard1.3/  lib/netstandard2.0/   ← 用这个
```

依赖：`System.Memory 4.5.5`。
→ **团结引擎自带** `MonoBleedingEdge/lib/mono/4.5/System.Memory.dll`，无需另装。

覆盖机型：S7-200 / S7-300 / S7-400 / S7-1200 / S7-1500。

### MQTTnet 4.3.7.1207

```
lib/netstandard1.3/  lib/netstandard2.0/  lib/netstandard2.1/   ← 用这个
```

依赖：**netstandard2.1 版本零依赖**。这是它比 S7netplus 更干净的地方。

> **版本红线**：MQTTnet **5.x 起基于 .NET 8**，Unity 2022.3 用不了。
> 5.0 与 4.3.7 的差别不是「新旧」，而是「能不能跑」。**不要随手升级。**

## 三、各通道的实现方式

### 3.1 SiemensS7Transport —— 批读批写 + 工作线程

S7 通道有两条工业现场的铁律，都体现在实现里：

| 铁律 | 实现 |
|---|---|
| **绝不每帧打 PLC** | `TryWrite` 只入待写队列；`Pump` 按 `PollIntervalMs`（默认 200ms）整批冲刷再整批回读 |
| **IO 不上主线程** | 所有 `Plc` 调用包在 `Task.Run` 里，主线程只读缓存 |

字节处理：S7 是**大端**，`DBD`（real）需要按 IEEE754 手工组装 int 位再 `BitConverter.ToSingle`。
这段在 `Decode` / `Encode` 两个静态方法里，是本类唯一不能简化的地方。

**点位表**：设备侧用逻辑标签（`AGV-01.PosX`），通过 `Map` 映射到真实点位（`DB1.DBD0`）。
没登记的标签读写一律失败 —— 这是刻意的，避免拼错地址时静默写坏 PLC 数据。

`TransportFactory.BuildS7` 会按设备顺序自动生成一张点位表，每台设备占 16 字节：

| 逻辑标签 | S7 点位 | 类型 |
|---|---|---|
| `<Id>.PosX` | `DB<n>.DBD<offset>` | Real |
| `<Id>.PosZ` | `DB<n>.DBD<offset+4>` | Real |
| `<Id>.Battery` | `DB<n>.DBD<offset+8>` | Real |
| `<Id>.Status` | `DB<n>.DBW<offset+12>` | Int |
| `<Id>.Online` | `DB<n>.DBX<offset+14>.0` | Bool |

6 台设备 = 96 字节，落在 `DB1.DBB0 ~ DB1.DBB95`。现场按实际点表改这个生成逻辑即可。

### 3.2 MqttTransport —— 主题即标签

MQTT 在工业侧管「纵向打通」（设备 → 平台 → 云端），因此映射规则最简单：

```
写 AGV-01.PosX   →  发布到  agv/AGV-01.PosX
订阅 agv/#       →  收到的值进入读缓存
```

协议版本设 `V500`。`PublishedCount` / `ReceivedCount` 两个计数暴露给 HUD，
用来确认链路真的在动 —— 而不是只看连接状态。

### 3.3 AbbRwsTransport —— 这一类不需要库

ABB 的 Robot Web Services **就是跑在控制器 80 端口的 REST 接口**，用 `UnityWebRequest` 直接请求即可。
社区项目 Unity3D_Robotics_ABB（MIT）示范的也是同一套做法，不必引它的代码。

| 端点 | 含义 |
|---|---|
| `/rw/motionsystem/mechunits/ROB_1/jointtarget` | 关节角度 |
| `/rw/motionsystem/mechunits/ROB_1/cartesian` | 笛卡尔位姿 |
| `/rw/rapid/execution` | RAPID 执行状态 |
| `/rw/panel/ctrlstate` | 控制器状态 |

实现要点：
- 请求串带 `?json=1` 让控制器返回 JSON；
- **轮转式请求**（每次只发一个），避免把控制器的 Web 服务打满；
- 只解析到「取回原文」为止，字段解析留给上层 —— 避免把某个控制器版本的 schema 焊死在传输层。

## 四、被排除的库及原因

### FluentModbus 5.3.2（Modbus）

包本身没问题，netstandard2.0/2.1 都有。但依赖链是：

```
Microsoft.Extensions.Logging.Abstractions 5.0.0
System.IO.Ports 5.0.0            ← 引擎不提供
System.Memory / System.Runtime.CompilerServices.Unsafe
```

`System.IO.Ports` 在团结引擎安装目录下**不存在**（仅为 Modbus RTU 串口所需，TCP 用不到，
但程序集引用必须能在加载时解析）。要引入就得自己补 3~4 个 DLL，
并承担 Unity 程序集校验的不确定性。**收益不抵复杂度，暂不引入。**

若确需 Modbus，两条路：
1. 自己抓 `System.IO.Ports` 的 dll 一并放进 `Assets/Plugins/`（能跑通但要试）；
2. 只用 TCP 时，Modbus TCP 报文很简单（MBAP 头 + PDU），手写一个 150 行左右的客户端反而更可控。

### realvirtual.io（AGV 路径 / 传送带 / 料流仿真）

三个硬约束叠加：
1. **要求 Unity 6**，本工程内核 2022.3；
2. AGV 路径仿真在付费版 **Simulation（540€）**，免费的 Starter 不含；
3. Starter 只提供基础框架 + S7 接口 —— 这两样本工程都已自行实现。

### ROS-TCP-Connector（无人机 / ROS2）

Unity 官方包，Apache-2.0，**要求 Unity 2022.3.62f2**（与本工程内核一致，版本无阻）。
但它是通过 **UPM Git URL** 安装：

```
https://github.com/Unity-Technologies/ROS-TCP-Connector.git?path=/com.unity.robotics.ros-tcp-connector
```

需要编辑器能访问 GitHub，且运行侧要有 ROS2 环境（`ros_tcp_endpoint`，端口 10000）。
代码怎么写可以直接参考 UNetyEmuROS（同为 2022.3.62 内核）。

**这是一个纯环境问题，不是兼容性问题** —— 你哪天真要接 ROS2，这一步没有技术障碍。

## 五、怎么切到真机

不需要改代码。选中场景里的 `AgvDemo` 对象，Inspector 上 `Device Fleet View` 组件的
**Transport Config** 里改 `Kind` 即可：

| Kind | 需要填 |
|---|---|
| `Simulated` | 什么都不用填，直接跑 |
| `SiemensS7` | `Host` = PLC 的 IP；`Cpu` 选机型；`Rack`/`Slot`（S7-1200/1500 通常 0/1） |
| `Mqtt` | `Host` = Broker 地址；`TopicPrefix` |
| `AbbRws` | `Host` = 控制器 IP；`Username`/`Password` |

`PollIntervalMs` 现场不要低于 100 —— 否则会打满控制器通信。

## 六、必须知道的局限

**这些实现只做过编译验证，没有接过真机。**

已验证的：
- ✅ 三个通道在 `dotnet` + 引擎参考程序集下编译零错误零警告
- ✅ 调用的 API 全部对着真实 DLL 核对过（`Plc.ReadBytes`/`WriteBytes`、`MqttFactory.CreateMqttClient` 等）
- ✅ 依赖链在引擎内可满足（`System.Memory` 实测存在）

未验证的：
- ❌ 未与真实 S7 PLC / MQTT Broker / ABB 控制器做过连通测试
- ❌ 字节序与数据类型换算未用真实 PLC 数据核对
- ❌ ABB RWS 的字段 schema 未针对具体控制器版本验证

首次接真机时，建议按这个顺序排查：**先用模拟通道确认上层逻辑 → 再单独用一个小脚本只读一个点位
→ 确认数值合理 → 最后开放批量读写在现场压力下验证。**
