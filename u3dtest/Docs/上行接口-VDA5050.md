# 上行接口（设备 → IoT 平台）

设备状态往上报的通道。载荷结构对齐 **VDA5050**（AGV 与主控系统之间的 MQTT 通信标准），
所以对接标准 WCS 还是你自己的 IoT 平台，都不需要改消息结构。

## 一、链路位置

```
SimulatedDevice / 真机
   │  每周期把状态与位置写进通道标签表
   ▼
ITransport（Simulated / S7 / MQTT / RWS）
   ▲
   │  TryWrite(主题, JSON载荷)
Vda5050Uplink（ITelemetrySink 的一个实现）
   ▲
   │  OnTelemetry(DeviceTelemetry)
DeviceGateway（按 PublishInterval 周期分发）
```

`Vda5050Uplink` 挂在 `DeviceGateway` 的 sink 列表里，和 `InMemoryTelemetrySink`（HUD 用）、
`JsonLineTelemetrySink`（本地调试用）并列。区别是：**前两个只把 JSON 存在内存里，
`Vda5050Uplink` 是真的通过 `ITransport` 发出去的。**

## 二、主题

VDA5050 标准主题结构：

```
{TopicPrefix}/{MajorVersion}/{Manufacturer}/{serialNumber}/state
```

经 `MqttTransport` 发布时，通道自身的 `TopicPrefix` 会再前置一层，所以**实际 MQTT 主题**是：

```
{TransportConfig.TopicPrefix}/{Uplink.TopicPrefix}/{MajorVersion}/{Manufacturer}/{serialNumber}/state
```

默认配置下的实例：

```
agv/vda5050/3/AgvDemo/AGV-01/state
agv/vda5050/3/AgvDemo/STK-01/state
agv/vda5050/3/AgvDemo/PLC-01/state
...
```

IoT 侧订阅 `agv/vda5050/#` 即可拿到全部设备的上行。

## 三、载荷

一条 `state` 消息（为了可读性做了换行，实际是单行 JSON）：

```json
{
  "headerId": 1,
  "timestamp": "2026-09-28T10:00:00.000Z",
  "version": "3.0.0",
  "manufacturer": "AgvDemo",
  "serialNumber": "AGV-01",
  "driving": false,
  "state": "IDLE",
  "stateCode": 1,
  "agvPosition": { "x": 1.25, "y": 2.5, "theta": 0 },
  "batteryState": { "batteryCharge": 0.8, "charging": false },
  "errors": []
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `headerId` | int | 单调递增的消息序号，每台设备独立计数。用于检测丢包 |
| `timestamp` | string | UTC，ISO-8601 带毫秒。VDA5050 要求 UTC |
| `version` | string | 协议版本 |
| `manufacturer` | string | 车辆厂商，对应 `UplinkConfig.Manufacturer` |
| `serialNumber` | string | 设备唯一标识，直接用项目里的设备 id |
| `driving` | bool | 是否在行走。由 `MachineState.Moving` 推导 |
| `state` | string | VDA5050 状态枚举，见下表 |
| `stateCode` | int | **非标准字段**。项目私有的 `MachineState` 整型编码，见下表 |
| `agvPosition.x` | number | 世界坐标 X，对应项目的 X |
| `agvPosition.y` | number | VDA5050 的 y 取项目里的 Z（Unity 是 Y 轴向上，语义对齐） |
| `agvPosition.theta` | number | 朝向角。本项目无导航层，恒为 0 |
| `batteryState.batteryCharge` | number | 电量 0~1 |
| `batteryState.charging` | bool | 是否在充电，由 `MachineState.Charging` 推导 |
| `errors` | array | 故障数组。本项目故障走 `DeviceFaulted` 进程内事件，这里恒为空 |

## 四、状态映射

| `MachineState` | `stateCode` | VDA5050 `state` |
|---|---|---|
| Offline | 0 | `COMM_ERROR` |
| Idle | 1 | `IDLE` |
| Moving | 2 | `MOVING` |
| Scanning | 3 | `WAITING` |
| Loading | 4 | `WAITING` |
| Processing | 5 | `WAITING` |
| Unloading | 6 | `WAITING` |
| Charging | 7 | `CHARGING` |
| Fault | 9 | `ERROR` |

**为什么需要 `stateCode`**：VDA5050 没有「扫码 / 取货 / 作业 / 放货」的等价枚举，四个状态都只能落到
`WAITING`。为了不丢信息，额外发一个 `stateCode` 承载项目自己的编码。
IoT 侧要区分「取货中」和「放货中」时用 `stateCode`，只做粗粒度监控时用 `state` 就够。

`MachineState` 的数值是**对外契约，一经现场使用就不能再改**，否则 `stateCode` 的语义会漂移。

## 五、开关与配置

在 `DeviceFleetSettings` → `Transport` → `Uplink` 里改，无需改代码：

| 字段 | 默认 | 说明 |
|---|---|---|
| `Enabled` | true | 关掉后上行出口不挂进网关，一条消息都不发 |
| `Manufacturer` | AgvDemo | 参与主题拼接，同时是载荷里的 `manufacturer` |
| `TopicPrefix` | vda5050 | 参与主题拼接 |
| `MajorVersion` | 3 | 参与主题拼接 |

上行频率由 `DeviceFleetSettings.PublishInterval` 控制（默认 0.5s），**每台设备每个周期一条**。

## 六、接你的 IoT 项目

1. 把 `TransportConfig.Kind` 改成 `Mqtt`，`Host` / `Port` 指向你的 Broker。
2. IoT 侧订阅 `{通道前缀}/{上行前缀}/#`，默认 `agv/vda5050/#`。
3. 解析 JSON。`serialNumber` 是设备标识，`state` + `stateCode` 是状态，`agvPosition` 是位置。

用 mosquitto 客户端手工验一条：

```bash
mosquitto_sub -h 127.0.0.1 -t 'agv/vda5050/#' -v
```

**两个注意点**：

- `SimulatedTransport` 下消息只落在内存数据块里，不出机器。要在本地看到真实上行，必须把 `Kind`
  改成 `Mqtt` 并有一个可用的 Broker。
- `MqttTransport` 会订阅 `{通道前缀}/#` 用于下行读缓存，因此它会收到自己刚发出的上行消息
  （MQTT 对匹配主题的订阅者会回送）。这会让 `ReceivedCount` 增长，属正常现象，不是重复发送。

## 七、怎么验证

```bash
# 单元测试：主题结构、JSON 载荷形状、状态映射、断线丢弃
# 链路测试：网关 → 上行出口 → 通道，确认消息真的落到了通道上
cd Tools/unit-tests && dotnet test UnitTests.csproj --nologo
```

`Vda5050Uplink` 支持注入时钟（构造函数第三个参数），因此测试能断言完整载荷字符串，
包括 `timestamp` 在内，不需要 JSON 解析器。

## 八、还没做的部分

- **下行**（`order` / `instantActions`）：IoT 侧下发任务、暂停、复位。目前项目只有进程内的
  `AdvanceDeviceRequest` / `SetAutoAdvanceRequest` 消息，没有走通道。
- **`connection` 消息**：VDA5050 要求设备上电时发一次 `online`、掉线前发 `offline`。
  目前只有周期性的 `state`，没有连接生命周期消息。
- **`orderId` / `nodeStates` / `edgeStates` / `lastNodeId`**：属于订单与导航层，
  本项目还没有路径规划，因此不输出。接 OpenTCS 这类真实调度后端时才有意义。
- **`errors` 填充**：把 `DeviceFaulted` 事件转成 VDA5050 的 error 对象数组。
