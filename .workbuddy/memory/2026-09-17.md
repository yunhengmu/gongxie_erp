## 撤回机制（冲账式）在 yudao 项目的最小落地方案

用户提供《基于冲账函数的可撤回 Agent 操作·设计文档（统一版）》，要求结合本项目给最小修改方案。

**已确认的项目事实（供后续复用）**：
- Java 侧 `module-ai` 是完整链路：`AiChatMessageController` → `AiChatMessageServiceImpl` → Spring AI `ChatModel` + `ToolCallbackResolver`；工具形态有两种：`tool/function/*ToolFunction`（`Function<Request,Response>` Bean，Bean 名登记在 `ai_tool` 表，如 `directory_list` / `weather_query` / `user_profile_query`）和 `tool/method/PersonServiceImpl` 的 `@Tool` 方法（`ps_*`）。
- Python 侧 `module-agent` 的工具（`core/tool/api_tools.py`）只是 HTTP 转发器，无真正业务写入；Agent 由 `core/agent.py:build_agent(kind, tenant_id, user_id)` 按请求组装，记忆 = LangGraph checkpointer + store。
- `ai_chat_message` 已有 `reply_id` 自关联（user 行 id 天然是 turnId）+ `@TableLogic deleted` + `tenant_id`。
- Java 侧 **没有** tool_call 落库表；对话上下文靠 `selectListByConversationId` 实时查（`filterContextMessages` 用 `reply_id == userMessage.id` 配对）。

**给出的方案要点**：
1. 1 张新表 `ai_reversible_ledger`（继承 `TenantBaseDO`）+ `@Reversible` 注解 + 入账切面 + UndoService；存量只改 2 处（Controller 加 undo 接口、一个真实业务工具加注解）。
2. 砍掉：独立 `turn_registry`（reply_id 已够）、反射兜底（getBean 必返代理）、archive/audit_log/idempotent_record/分表/tenant_quota/tenant_sequence。
3. 关键坑：冲账方法**必须定义在接口上**（`ReversibleTool`），否则 JDK 代理下 `getBean` 拿不到该方法；不能赌 Spring Boot 默认 CGLIB。
4. 并发用 DB 状态 CAS（`UPDATE ... WHERE status='POSTED'`）占位，不需分布式锁。
5. "三删"里两删免费：对话记忆 = 逻辑删（@TableLogic 自动从 Prompt 上下文消失），工具历史 = 本项目未落库。

**顺带发现（待用户确认）**：`yudao-module-agent/core/agent.py:11` 引用 `core.tool.memory_tools_tenant`，但该文件在仓库中不存在，启动会 ImportError。疑为本地未提交文件或删除后的残留引用。

**本次未修改任何项目代码文件**，仅输出方案与一张说明图。

## 追加：撤回单元定为 messageId + AOP 封装的传递通道调研

用户决策：① 撤回用前端传 `messageId`（不是"最近一条"）；② 先封装 AOP 这层，业务样板工具暂不选。

**决定性发现 —— turnId 的传递通道 = Spring AI `ToolContext`（已验证可行）**：
- `UserProfileQueryToolFunction`（`module-ai/tool/function/`）已经是
  `implements BiFunction<Request, ToolContext, Response>`，`apply(Request, ToolContext)` 里读
  `AiUtils.TOOL_CONTEXT_TENANT_ID` / `TOOL_CONTEXT_LOGIN_USER`；`DbQueryToolFunction` 同款。
- `AiUtils.buildCommonToolContext()`（`AiUtils.java:156`）把 loginUser + tenantId 塞进 Map，
  经 `AiChatMessageServiceImpl.java:379` → `AiUtils.buildChatOptions(..., toolContext)` → `ChatOptions.toolContext()` 下传。
- 所以加一个 `TOOL_CONTEXT_MESSAGE_ID = "MESSAGE_ID"` 就能把 turnId 送到工具执行侧。
- **不要用 ThreadLocal**：`sendChatMessageStream` 的 `chatModel.stream(prompt)` 里工具在 Flux 线程执行，
  项目代码自己就有注释佐证（`TenantUtils.executeIgnore`："Flux 异步无法透传租户"）。
- Spring AI 版本 = **2.0.0**（`yudao-module-ai-server/pom.xml:22`）。
- 约束：可撤回工具必须是 `BiFunction<Request, ToolContext, Response>` 形态（单参 `Function<Request,Response>`
  的 `DirectoryListToolFunction` / `WeatherQueryToolFunction` 拿不到 ToolContext，无法入账）。

**AOP 三个坑（已写入方案）**：
1. `@Reversible` 必须加在**实现类**方法上 —— Spring AOP 的 `@annotation` 切点匹配不到接口上的注解。
2. 冲账必须走**统一接口**（`getBean(name, ReversibleTool.class)`），否则 JDK 代理下 `getBean` 返回接口代理、
   反射取不到实现类方法；不要做反射兜底。
3. 切面拿不到 messageId 时要 fail-fast 抛异常，**不可静默跳过**——否则"以为可撤、实际无账本"。

**messageId 版撤回比"最近一条"多一道因果闸门**：允许点选任意消息，但必须校验
"该 conversation 下不存在 message_id 更大的 POSTED 帧"，否则会出现后序操作变孤儿。失败提示"请先撤回更晚的消息"。

## 追加：AOP 封装的契约与表结构定稿

**切面事务边界（结论）**：
- 入账切面：用 `TransactionTemplate.execute()` 显式把 `proceed()` + 写帧包在**同一事务**，不要用 `@Transactional` 注解
  （避免与 `@Transactional` 默认 LOWEST_PRECEDENCE 的 order 心智负担）。业务抛异常 → 帧不入 → 整体回滚。
- 冲账切面：每条帧 **REQUIRES_NEW**，失败不影响已成功的帧（对应文档"冲账独立提交"）。
- 正向幂等 MVP 不做（Spring AI 不重试）；冲账幂等靠 status CAS。
- `seq` 字段砍掉：`id` 自增天然有序，足够支持同一 message 内逆序冲账。

**`ReversibleContext` 字段**：ledgerId / messageId / toolName / bizVoucher（必用，冲账定位原分录）/
rawInput(JSON) / tenantId / operatorId / reason / reversedAt。类型问题用 `ctx.input(Class<T>)` 泛型反序列化解决，
不让框架猜参数类型（对应文档"不依赖反射时的参数推断"）。

**表 `ai_reversible_ledger`**：id, conversation_id, message_id, tool_name, tool_input(json), biz_voucher,
reverse_bean, reverse_method, status(0 POSTED/10 REVERSING/20 REVERSED/30 FAILED), reversed_voucher,
reverse_reason, reversed_time + TenantBaseDO 审计字段。
索引：`(tenant_id, message_id)` 查单条消息的帧；`(tenant_id, conversation_id, status, id)` 支撑因果闸门。
注意：账本是 append-only，`deleted` 字段保留以符合芋道规范但**不提供删除入口**。

**两个坑**：
1. 可撤回工具**不能吞异常**（不能 try-catch 后返回友好字符串），否则失败会被当成成功入账。
   参考反例：`yudao-module-agent/core/tool/api_tools.py` 全量 try-except 返回字符串。Java 侧现有工具无此问题。
2. 只读工具（directory_list / weather_query / user_profile_query）不加 `@Reversible`，天然不进账本。

**实现期修正了方案里的 3 个错误**：
1. **工具形态搞错了**：`DbQueryToolFunction` 不是 `BiFunction`，是「普通类 + `@Tool` 方法 + ToolContext 参数」。
   所以 `@Reversible` 要支持两种形态。真正不合格的只有单参 `Function`（`directory_list`/`weather_query`）。
2. **工具名 ≠ Bean 名**（真 bug，已修）：`@Component("xxx")` 形态二者相同；`@Tool(name="yyy")` 形态工具名是注解值。
   切面原用 Bean 名当 `tool_name`，会让账本与 `ai_tool` 表对不上。已加 `resolveToolName()`：`@Tool(name)` 优先、Bean 名兜底。
3. **按类型反查 Bean 名**：给 `resolveBeanName` 加了 `ConcurrentHashMap` 缓存，避免每次工具调用都 `getBeanNamesForType` 遍历容器。
