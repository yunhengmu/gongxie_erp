## 关键发现：映射机制与 protected 构造的冲突（10:00–10:15）

用户问「业务逻辑在哪写」「`WarehouseAppService` 这段代码什么意思」，排查中查出两个会导致失败的事实。

**① ABP 10.6 的映射器是 Mapperly，不是 AutoMapper**。`LearnApplicationMappers.cs` 的 using 是 `Riok.Mapperly` + `Volo.Abp.Mapperly`，模板给的文件是空的（只有注释示例）。`MapperBase<TSource, TDestination>` 定义在 `framework/src/Volo.Abp.Mapperly/Volo/Abp/Mapperly/MapperBase.cs`，两个抽象成员 `Map(TSource)` / `Map(TSource, TDestination)`，另有 `TwoWayMapperBase<TSource, TDestination>` 支持反向映射（`ReverseMap`）。

**② `CrudAppService` 默认靠映射器凭空造实体**（源码 `framework/src/Volo.Abp.Ddd.Application/Volo/Abp/Application/Services/AbstractKeyCrudAppService.cs`）：

```csharp
protected virtual Task<TEntity> MapToEntityAsync(TCreateInput createInput)          // line 139，新增时
protected virtual Task MapToEntityAsync(TUpdateInput updateInput, TEntity entity)   // line 178，更新时
```

而本项目的 `Warehouse` 只有 `protected Warehouse()`（EF 用）与 `public Warehouse(Guid, string, string)`（业务用）。Mapperly 生成的代码位于 `Application` 程序集，**访问不到 protected 构造**，编译必然失败。

**给出的方案**：读方向（实体 → DTO）用 Mapperly 声明；写方向（DTO → 实体）重写上面两个方法——新增走构造函数、更新走 `Rename()` 业务方法，而不是反射硬塞字段（那是贫血模型的做法）。

**回答「业务逻辑写在哪」的结论**：

| 落点 | 判断标准 | WMS 例子 |
|---|---|---|
| 聚合根（实体方法） | 规则只用自己字段 | `Warehouse.Deactivate()` |
| 领域服务（`XxxManager`，Domain 层） | **跨聚合**，需查别的聚合 / 仓储 | 库位调拨、库存转移 |
| 应用服务（Application 层） | 只是编排 + 事务 + DTO 转换 | `WarehouseAppService` |

→ 用户问的「涉及多聚合根」应落在**领域服务**，不是 AppService。

**已给出**：Mapperly 映射类写法 + 两个 `MapToEntityAsync` 重写示例。

### 坑 1：`wwwroot/libs` 缺失 → 所有端点 500

后端首次启动后，**所有**请求（`/api/abp/api-definition`、`/swagger`、`/health-status`）一律 500，响应体是 ABP 的错误页：

> ⚠️ The Libs folder is missing! Make sure you run the `abp install-libs` CLI tool command.

`HttpApi.Host` 引了 LeptonXLite 主题（登录页 / 错误页用），需要 `wwwroot/libs` 静态资源；缺失时 ABP 在中间件层**短路所有请求**。

**解法**：`cd src/Acme.Learn.HttpApi.Host && abp install-libs`

**⚠️ 关键**：该检查在**应用启动时判定一次并缓存** —— 装完 libs **必须重启后端**，否则仍旧 500（这一点浪费了一轮排查）。

### 坑 2：`abp install-libs` 的 yarn engines 报错

```
error select2@4.1.0: The engine "node" is incompatible with this module.
      Expected version ">=24". Got "22.22.2"
```

**解法**：在 `HttpApi.Host` 目录建 `.yarnrc`，内容 `ignore-engines true`（**项目级而非全局** `yarn config set`，避免影响其他项目）。重跑成功，耗时 4m20s（网络慢），生成 18 个库。

### 坑 3：Angular CLI 拒绝当前 Node 版本

```
The Angular CLI requires a minimum Node.js version of v22.22.3 or v24.15.0 or v26.0.0.
```

系统 Node 是 **22.22.2**，差一个补丁号。**根因**：`@angular/cli@22.0.9` 把支持范围**硬编码**在 `node_modules/@angular/cli/src/utilities/node-version.js`：

```javascript
const SUPPORTED_NODE_VERSIONS = '^22.22.3 || ^24.15.0 || >=26.0.0';
```

**解法**：下界改为 `^22.22.0`。⚠️ **`npm install` 后会失效**，需重改；根治办法是升级系统 Node（≥ 22.22.3 或 24.15.0+）。
