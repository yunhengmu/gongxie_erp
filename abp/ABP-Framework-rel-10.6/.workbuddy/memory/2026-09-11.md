### 交付物

设计结论：
- **7 个聚合根**：Warehouse / Material / Location / InboundOrder / OutboundOrder / Inventory / InventoryTransaction
- **2 个聚合内实体**：InboundOrderLine / OutboundOrderLine
- **3 个领域服务**：InventoryManager（跨聚合库存，必须）/ InboundOrderManager / OutboundOrderManager（单号）
- 核心是 **2 个状态机 + 1 个库存一致性模型**
- 设计顺序：画状态机 → 定库存加减时机 → 定聚合边界 → 最后写实体类（与「先建表」完全相反）

关键设计决策（用户会追问的点）：
- **Location 独立成聚合根**（业务上依附 Warehouse，但查询频率高，属性能妥协）
- **单据行必须是聚合内实体**（与单头共享「不可重复物料」不变量）
- **库存采用「流水 + 实时表」双表**（方案 B）
- **AllocatedQuantity 预留机制**（`AvailableQuantity = Quantity - AllocatedQuantity`）
- 流水表基类用 `CreationAuditedAggregateRoot`（无软删无修改审计，因流水只增不改）
- `InboundOrderLine` 构造器与 `Receive` 用 `internal`（AppService 调不到，实现聚合封装硬约束）
