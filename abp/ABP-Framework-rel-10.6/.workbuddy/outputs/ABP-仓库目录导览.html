## Adding a New Entity (Full Flow)

### 1. Domain Layer
Create entity (location varies by template: `*.Domain/Entities/` for layered,
`Entities/` for single-layer/microservice):

public class Book : AggregateRoot<Guid>
{
    public string Name { get; private set; }
    public decimal Price { get; private set; }

    protected Book() { }   // 给 ORM

    public Book(Guid id, string name, decimal price, Guid authorId) : base(id)
    {
        Name = Check.NotNullOrWhiteSpace(name, nameof(name));
        SetPrice(price);
    }

    public void SetPrice(decimal price)
        => Price = Check.Range(price, nameof(price), 0, 9999);
}
...

07给你的阅读路线建议

仓库有 2 万多个文件，漫无目的地翻必然迷路。按下面这个顺序走，两周能建立完整认知。

  1. 第一天 · 建立规范认知（约 1 小时）
    读这三份，它们决定后面所有代码长什么样：
    ai-rules\common\dependency-rules.mdc（分层依赖）
    ai-rules\common\ddd-patterns.mdc（DDD 模式）
    .cursorrules（扫一遍标题，当手册备查）
  2. 第二天 · 看一个真实业务怎么写的（半天）
    打开 modules\blogging\，沿着 Post 这条垂直切片横着读一遍：
    实体 → 仓储接口 → 仓储实现 → DTO → AppService 接口 → AppService 实现 → 控制器。
    这是全仓库最适合初学者的一份材料：真实、完整、没有占位名。
  3. 第三、四天 · 理解项目骨架（1 天）
    打开 templates\app\，对照《ABP 文件路径总索引》把七层目录走一遍。重点看每个 *Module.cs 里的 [DependsOn]——那才是模块关系的真相。
  4. 第五天起 · 动手（持续）
    用 abp new 建自己的项目，照着 .agents\skills\abp-development-flow\SKILL.md 走一遍「新增实体」的全流程。踩一次坑胜过读十遍文档。
  5. 按需 · 深挖框架内部
    遇到「这个基类到底给我加了什么」时再去 framework\src\Volo.Abp.XXX\。

一个提效技巧：那 18 个 AI 技能文件（.agents\skills\）是被设计成给 AI 助手读的。你完全可以让 AI 直接读这些文件再回答你的问题——它比读整个文档站更聚焦，而且代码范式是经过校验的。
