找文件不再迷路：ABP 仓库完整路径索引

工作区根目录：D:\yudao\abp\ABP-Framework-rel-10.6。本文所有路径均为可直接复制粘贴的完整路径，按「我要找什么 → 去哪」组织，所有条目均已实地核验存在。

先看这一条，否则你永远找不到文件：模板里的路径全是「占位名」。

ABP 官方模板为了能生成任意项目，把公司名和项目名做成了占位符：MyCompanyName.MyProjectName（C# 侧）和 my-project-name（Angular 侧）。你在仓库里看到的 MyCompanyName.MyProjectName.Domain 不是某个真实项目，它是「假设你叫 MyCompanyName、项目叫 MyProjectName」时的样子。

当你真正执行 abp new Acme.BookStore 生成自己的项目后：

  • MyCompanyName.MyProjectName.Domain → Acme.BookStore.Domain
  • MyProjectNameDomainModule.cs → BookStoreDomainModule.cs
  • my-project-name/ → book-store/

所以读模板时请把占位名当变量看；本索引里凡出现占位名的路径，我都会标注 占位名。

app 模板与 module 模板在 EF Core 层有一处实质差异，别找错文件：

  • app 模板：没有 MyProjectNameDbContextModelCreatingExtensions.cs。实体映射直接写在 MyProjectNameDbContext.cs 的 OnModelCreating() 里（该文件内已留好注释掉的 builder.Entity<YourEntity>(...) 模板）。
  • module 模板：有独立文件 MyProjectNameDbContextModelCreatingExtensions.cs，并且还有独立的 IMyProjectNameDbContext.cs 接口。这是官方推荐写法（见 .cursorrules：Do NOT configure entities directly inside OnModelCreating）。

所以如果你照着 module 模板的规范写，但项目是基于 app 模板建的，可以自己把映射抽到独立的扩展方法里。

命名规律速记（比背路径更管用）：

  • 每层都有且仅有一个模块类：MyProjectName<层名>Module.cs
  • 每个聚合根一对：Xxx.cs（Domain）+ IXxxRepository.cs（Domain）+ EfCoreXxxRepository.cs（EFCore）
  • 契约三件套：IXxxAppService.cs（Contracts）+ XxxAppService.cs（Application）+ XxxController.cs（HttpApi）
  • DTO 四件套：XxxDto.cs（详情）+ CreateXxxDto.cs + UpdateXxxDto.cs + GetXxxListDto.cs
  • 业务目录名在七层里保持一致（都叫 Products\），所以顺着目录名横着走就能穿完整个链路

掌握这五条，你在 IDE 里搜一个业务名，七层的文件会一起出现。
